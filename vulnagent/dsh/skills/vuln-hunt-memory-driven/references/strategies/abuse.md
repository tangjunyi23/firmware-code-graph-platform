# 业务逻辑滥用 专项分析策略

**红队视角**：业务逻辑滥用漏洞在红队报告中通常作为补充发现，但某些场景（如未认证邮件洪水可用于钓鱼）具有实际利用价值。

**Sources：**
- 触发邮件发送的 API 接口（邀请、密码重置、通知、验证码）
- 触发短信发送的 API 接口
- 触发外部请求的 API 接口（webhook、回调）
- 涉及金额/积分/配额的 API 接口
- 用户注册/创建资源的接口

**Sinks：**
- 邮件发送函数（smtp.send/sendmail/SES/SendGrid）
- 短信发送函数（Twilio/SMS API）
- HTTP 外发请求函数（用于 webhook/通知）
- 数据库写入（资源创建/配额变更）

**Key Check：**
1. **速率限制缺失**：触发邮件/短信/通知的接口是否有速率限制（rate limit）？未限制时可大量触发消耗服务器资源或骚扰目标。
2. **认证要求**：触发外发通信的接口是否需要认证？未认证端点可被任意调用。
3. **接收者可控**：邮件/通知的接收者地址是否来自请求参数？可控接收者 + 无速率限制 = 邮件炸弹。
4. **内容可控**：邮件/通知的内容是否包含用户可控部分？可控内容可用于钓鱼攻击。
5. **CAPTCHA 保护**：敏感操作（注册、密码重置）是否有验证码保护？
6. **资源耗尽**：批量创建操作是否有数量限制？

**Common Patterns：**
- `POST /api/invite` 无认证 + 无速率限制 + 接收者来自请求参数 → 邮件洪水
- `POST /api/password-reset` 无速率限制 → 对目标用户发送大量重置邮件
- `POST /api/webhook/test` 无认证 + URL 来自请求参数 → SSRF + DoS
- 注册接口无 CAPTCHA → 批量注册垃圾账户
